# Contribution workflow

- Work on feature branches. Do not commit or push directly to `main`.
- Use Conventional Commits for commit messages and pull request titles (for example, `feat:`, `fix:`, and `docs:`).
- Submit changes through pull requests. Review the diff and run the relevant checks, then merge into `main` once the change is ready.

# Public writing

- Keep public docs, pull requests, and release notes focused on the app and user-visible changes.
- Keep machine names, personal paths, account details, and detailed test-environment records in local validation files. Publish only compatibility and validation details that help someone use or review the app.
